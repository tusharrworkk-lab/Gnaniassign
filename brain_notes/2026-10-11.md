## Gnani realtime speech-to-text

Source: [Speech-to-Text (Realtime)](https://docs.gnani.ai/api/STT/stt-websocket). The product list is in the [Speech APIs introduction](https://docs.gnani.ai/api/introduction/introduction). Model name in the docs is Gnani Prisma v2.5. Base URL is `https://api.vachana.ai`.

The live endpoint is one WebSocket, `wss://api.vachana.ai/stt/v3/stream`. Audio goes up as raw PCM frames, 1,024 bytes each, about every 32 ms at 16 kHz. The socket stays open. Configuration, including language and the silence timer, is sent as headers when the socket opens.

Gnani does not send a running guess. Voice activity detection waits until speech stops. Silence must last `x-min-silence-ms` before a piece closes. The default is 500 ms. The transcript cannot arrive before that timer ends.

For each closed piece the server sends two messages:

1. `processing` — speech has ended and transcription has started.
2. `transcript` — the text of that whole piece, plus `segment_id`, `segment_index`, `audio_duration_ms`, and `latency` (milliseconds from the detected end of speech to the text).

That `transcript` is already final. The next message does not replace it. The next `transcript` is the next time the person pauses.

“Book a meeting on Thursday,” said with no half-second gap, arrives as one `transcript` after the pause at the end. It does not arrive as “book a meeting” and then “on Thursday.” Those become two transcripts only if there is a real pause between them long enough for the silence timer, or if `x-max-speech-s` is set so a long stretch is cut even without a pause.

A lower `x-min-silence-ms` returns shorter pieces sooner. It also cuts a sentence at a breath. The docs suggest about 400–600 ms for a phone conversation and 600–900 ms when a full sentence matters more than speed.

REST speech-to-text is a different path: one clip, up to 60 seconds, one HTTP response. Batch is for long files. Neither is the live call.

## What this does to the pipeline

In `TurnSession`, each Gnani `transcript.text` is one `feed_final`. The pause has already happened by the time the text exists, so Laya and the subagent start then, not while the words are still being spoken.

The graph can still join several transcripts into one sentence and keep or drop a draft when the next pause adds a day or a person. It cannot draft “book a meeting” while “on Thursday” is still being said, unless those two were already split by a pause.
