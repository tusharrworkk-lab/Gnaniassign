# Brain notes — 11 October 2026, second edition

Continues `2026-10-11.md`. After the Gnani speech-to-text note, the decision step was timed with Jev, then the routing and the context window were tightened so a long call does not get slower.

## Jev in the pipeline

`check.py` calls Jev (`typesafe/jev-1.13` on OpenRouter) instead of local Laya. `JevRouter` in `jev.py` has the same `predict()` shape the graph already uses. The API key is read from `OPENROUTER_API_KEY`. It does not live in the source.

One simulated call, three decisions, on “book a meeting” then “on Thursday with Priya,” then the pause:

| Step | Graph | Jev | Result |
|---|---|---|---|
| “book a meeting” | 1087 ms | 1068 ms | `book_meeting` 0.94. Draft asks for the day. Nothing spoken. |
| “on Thursday with Priya” | 562 ms | 556 ms | `book_meeting` 0.95 and `take_note` 0.61. Day and person changed, so the draft was rewritten. |
| Pause | 571 ms | 567 ms | Same intent and slots. Draft reused, then spoken. |

Call total: **2220 ms**. The subagent text is a few milliseconds. Almost all of the wait is the Jev round trip. The pause still calls Jev, because the graph decides again before it notices the draft can be kept.

Local Laya on the 1650 Ti, measured the same day earlier, was about 240 ms for four questions once a single FP16 checkpoint was loaded. Jev is slower here because it is a network call. Laya is slower than its model-card figure because that figure is a T4, not this laptop.

## One class, then one subagent

A help-and-support sentence should be labeled `help_support` and sent only to that agent. Do that with one Laya or Jev choice, not a separate yes/no for every intent:

- `help_support` — the caller needs help or something fixed
- `book_meeting` — book, move, or cancel a time
- `take_note` — save what was said
- `about_me` — who the user is
- `other` — anything else

Five classes in one question is less work than three separate checks. On the Jev timing run the second phrase was both a meeting and a note, so two replies were built. One class means one subagent and one generation.

Laya does not speak, so a shorter Laya prompt does not make the voice faster. The speaking model is the one that grows with tokens. It should see only the chosen agent’s short prompt.

## The text window stays. The request does not grow.

The full call can sit in a list on the phone. Latency stays flat only if that list is not pasted into every model call.

Three stores, each a fixed size:

- **This sentence.** Locked phrases since the last pause. Dropped after the reply is spoken.
- **Open facts.** A few fields, overwritten when they change: last intent, day, person, and anything still unresolved. Not a growing paragraph.
- **One summary line.** At the pause, fold the turn into that line and drop the raw words. The next turn replaces the line. It does not stack another one under it.

Laya or Jev receives only this sentence. The speaking agent receives its prompt, the summary line, the open facts, and this sentence. A later “what day?” reads the `day` field. If that field was never saved, ask again. The old transcript is not sent back through the model.
